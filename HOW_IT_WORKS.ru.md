# Как работает мем-архив

Технический осмотр внутренних устройств. `README.md` описывает использование; в этой статье объясняется оборудование.

## 1. Общая картина

Meme Archive - это однопроцессное приложение FastAPI, которое превращает изображения в текст для поиска:

```
image bytes -> SHA-256 id -> Gemini description -> embedding vector -> ChromaDB
```

Поиск встраивает * запрос пользователя * и сравнивает векторы в ChromaDB (косинусное расстояние), поэтому «кот в офисе» находит мем, даже если ни одно имя файла не упоминает его. Блокирующая работа выталкивается из цикла событий с помощью `run_in_threadpool`.

|Модуль|Роль|
| --- | --- |
| `app/main.py` |маршруты, аутентификация, срок службы, фоновые задачи|
| `app/service.py` |add / search / list / similar / tags / delete;|
| `app/ai.py` |Описание Близнецов + встраивание, кэш, логика ограничения скорости|
| `app/db.py` |Обертка ChromaDB|
| `app/embed_cache.py` |постоянный кэш встраивания запросов SQLite|
| `app/pending.py` + `app/moderation.py` |очередь модерации, согласования, Telegram|
| `app/captcha.py` |саморисованная капча|
| `app/images.py` |валидация, хеширование, теги, безопасность пути|
| `app/ingest.py` + `app/scheduler.py` |импорт фоновой папки|
| `app/stats.py` |Счетчики JSON|
| `app/config.py` |pydantic-settings от `.env`|

## 2. Хэш контента - первичный ключ

`images.sha256_bytes` — идентификатор каждого изображения **является** SHA-256 его байтов. Это дает:

- **Идемпотентность * *: повторная загрузка одних и тех же байтов никогда не запускает Gemini повторно. `service.add_image` сначала проверяет хэш (service.py:106); если он существует, он объединяет только теги/избранное и повторно создает файл, если он отсутствует.
- ** Макет хранилища **: файлы `<hash>.<ext>` в `uploads/`, записанные через временный файл + `os.replace` (`_write_atomic`), поэтому крэш никогда не оставляет наполовину написанные файлы.
- ** Дедупликацияпо источникам**: веб-загрузка, импорт папок и повторное одобрение - все это безобидно сталкивается с одним и тем же хешем.

Расширение происходит из формата, обнаруженного подушкой, а не из загруженного имени файла.

## 3. Загрузить конвейер

Капча (`captcha.py`): сервер выбирает случайное число 100-99999, отображает его ** русскими словами** над линиями шума/точками с подушкой, и ожидаемый ответ - цифровая форма. Бот не может распознать это тривиально; человек читает слова и печатает цифры. Задачи живут в диктовке в памяти с TTL; `verify()` всплывает запись (однократное использование) и сравнивается с `hmac.compare_digest`.

`POST /add` (main.py:197):

1. Проверьте капчу, иначе `CaptchaError`.
2. Если `PENDING_TTL_SECONDS > 0` -> `moderation.submit_upload`, ответьте `202 pending`; в противном случае `service.add_image` напрямую ответьте `200`.

## 4. Валидация и безопасность пути (`images.py`)

Порядок `inspect_image`: отклонить пустые байты -> отклонить > `MAX_UPLOAD_MB` -> `PIL.Image.open().verify()` (формат определен из **содержимого**, не имени) -> только разрешенные форматы (JPEG/PNG/WEBP/BMP/GIF) -> отклонить > `MAX_IMAGE_PIXELS` (останавливает декомпрессионные бомбы).

`safe_upload_path` отклоняет все, что не является пустым именем файла (нет `/`, `\`, NUL, `..`) и проверяет, что разрешенный родитель равен каталогу загрузок, поэтому `/image/{filename}` не может пройти; небезопасные или неизвестные имена отвечают как общее «не найдено».

## 5. Слой Близнецов (`ai.py`)

**Описание**: необработанные байты + подсказка от `prompt.txt` перейти к `RECOGNIZING_MODEL.generate_content`. Подсказка запрашивает завершающую * * строку ключевого слова * *; `images.extract_tags` разделяет ее на 3 автоматических тега (проверка последней строки выглядит как короткие сегменты, разделенные запятыми).

**Встраивание**: `embed_content` с асимметричными типами задач — `RETRIEVAL_DOCUMENT` для описаний, `RETRIEVAL_QUERY` для поисков (рекомендуемое разделение документов/запросов Gemini).

**429 handling**: на `ClientError.code == 429`, `_parse_retry_delay` извлекает подсказку сервера `retryDelay: '995s'` / "retry in 16m35s". Если разрешены повторные попытки (макс. 3) и задержка (макс. 900 с), спать и повторить попытку на месте; в противном случае вызов прекращается и отмечает **глобальное окно блока ** (`_mark_blocked`). `upstream_blocked_seconds()` консультируется с циклом автоматического утверждения и проглатыванием папки, чтобы фоновая работа не забивала дросселированную квоту. Интерактивный поиск проходит `bypass_delay=True` (service.py:327): пользователь браузера никогда не спит минуты, он просто получает «try later».

** Кэш встраивания **: внутрипроцессный LRU `OrderedDict` (4096), введенный `(normalized_text, task_type, model)`; точное попадание, в противном случае нечеткое попадание через `rapidfuzz token_sort_ratio >= 90` с той же задачей/моделью. Промахи попадают в Близнецы и сохраняются в SQLite (`embed_cache.db`) в виде blob-объектов float64 с `last_used`. При перезапуске `load_into` (ai.py:76) перезагружает самые свежие 4096 строк — кэш переживает перезапуск; вытеснение LRU также удаляет дисковые строки. Питание счетчиков `/stats`.

## 6. ChromaDB (`db.py`)

Одна постоянная коллекция `images` с `hnsw:space=cosine`: id = хэш, document = описание, embedding = вектор документа, metadata = `stored_name`, `source`, `original_filename`, `tags`, QQZ6QZQ, `pending`, dimensions, `created_at`, `added_via`. Метаданные пустого списка отбрасываются (`_clean_metadata`). Пагинация: извлечение `n_results + offset`, затем срез; фильтры `where` (`tags $contains`, `favorite`, `pending`) сдвинуты вниз.

`service._build_record` восстанавливает все, что показывает пользовательский интерфейс, с резервными копиями для записей, записанных более старыми версиями.

## 7. Поиск (`service.search`)

1. ** Ярлык тега **: если запрос точно соответствует существующему тегу (без учета регистра), все его мемы возвращаются первыми и исключаются из семантического пропуска — одно поле поиска удваивается как просмотр тега.
2. **Семантический проход**: вставьте запрос (`RETRIEVAL_QUERY`) и запустите `db_search`.

Записи, файл которых исчез с диска, пропускаются, а не отображаются сломанными.

Другие режимы: `list_images` (порядок подачи `new|old|top|random`, «новый» = хвост обратного порядка вставки Chroma), `get_similar_images` (повторно использует сохраненный вектор через `db_get_embedding`, нулевые вызовы Gemini), `get_random_image` (случайное смещение в отфильтрованный `get()`).

## 8. Очередь модерации (`pending.py` + `moderation.py`)

Очереди мемов живут **вне** Chroma, поэтому неутвержденный контент никогда не индексируется. `pending_dir` содержит файлы изображений плюс `index.json` (id -> record with `expires_at`), переписанные атомарно под блокировкой.

`submit_upload`: уже заархивировано -> мгновенное добавление; уже в очереди -> дублирующая ожидающая запись; очередь >= `MAX_PENDING_ITEMS` -> 429. Новые элементы получают уведомление Telegram `sendPhoto` в чат администратора (`telegram.py`, сбои зарегистрированы, никогда не блокируйте загрузку).

`auto_approve_loop` (запущен в `lifespan`, main.py:83) пробуждает каждый элемент `PENDING_CHECK_INTERVAL`; для каждого элемента due он вызывает `approve()`, который повторно запускает `service.add_image` на сохраненных байтах — описание + встраивание, поэтому происходит **во время публикации **, когда квота может быть восстановлена. Защитные ограждения: в то время как `ai.upstream_blocked_seconds() > 0` цикл ничего не делает; ошибка восходящего потока останавливает пакет до следующего цикла. Администраторы могут одобрить/отклонить на ранней стадии через `/api/v1/admin/*`.

## 9. Импорт папок (`ingest.py` + `scheduler.py`)

Фоновая задача сканирует `MEME_IN_DIR` каждые `SCAN_INTERVAL`, вызывая `service.add_image(added_via="folder")` на файл — тот же путь дедупликации/описания, что и при загрузке. Политика: пропустите проход полностью, пока Близнецы заблокированы; посчитайте последовательные ошибки восходящего потока, прервите проход после `UPSTREAM_FAILURE_STREAK` (5); `next_scan_delay` удваивает интервал за прерванный проход до `SCAN_BACKOFF_MAX` (30 минут); чистый проход сбрасывает его.

## 10. Аутентификация и ошибки (`main.py`)

Два независимых токена по сравнению с `secrets.compare_digest`, принимаемых через `X-API-Key` или `Authorization: Bearer`:

- `BOT_API_TOKEN` ворота `/api/v1/*` (API бота: поиск, случайный, похожий, загрузка изображений). Пусто = открытый API.
- `ADMIN_TOKEN` ворота `/api/v1/admin/*`, избранное/удалено на `/images`. Empty = admin features answer 503.

`AppError` отображает подклассы для очистки JSON `{"detail": ...}` без внутренних элементов; всеобъемлющий обработчик регистрирует обратную связь и возвращает общий 500.

## 11. Интерфейс и статистика

Обслуживаемые сервером страницы `/` (feed + search), `/meme/{id}` (card), `/admin` (queue with countdown, counters, approve/reject/delete); активы под `/static`, токен администратора хранятся только в `sessionStorage`. `stats.py` хранит счетчики (`description_calls`, `cache_*`, `uploads_*`, `captcha_failures`, ...) в памяти, сохраняется до `stats.json` атомарно под замком и экспонируется через `/stats`.

## 12. Переиндексация

Векторы из старого `EMBEDDING_MODEL` несовместимы с новыми. `python -m app.reindex` повторно встраивает каждое сохраненное описание; `--prune` также удаляет записи, файл которых исчез.
